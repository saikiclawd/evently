Section 2 — Business Problem

What's broken today

Nine distinct failure modes in current manual floral operations — each with measurable business impact.

🧮

Stem Calculation Errors

Manual multi-tab spreadsheets break on formula errors and stale references. One transposed digit on a 300-stem wedding = $400–$900 in surplus or shortfall.

🌸

Missing Flower Types

No standardised recipe library means personal templates diverge. On event handoffs, entire varieties are omitted from orders without any system warning.

📦

Over / Under Ordering

No historical data or buffer logic. Buyers either over-order (waste) or under-order (day-of substitutions at retail premium — highest possible cost).

✖️

Wrong Recipe Scaling

A recipe for 10 centerpieces scaled to 24 by hand — multiplication errors compound across multi-variety arrangements with no automatic verification.

📝

No Version Control

Spreadsheets are overwritten. No audit trail for who changed a recipe, when, or why. Accountability gaps and recipe regression with no recovery path.

🏷️

Inventory Mismatch

Physical stock not reconciled against event requirements. Result: double-purchasing already-in-stock stems and avoidable cost increases.

🔮

No Forecasting

Orders placed event-by-event with zero visibility into upcoming demand. Volume discounts and consolidated multi-event orders are impossible.

🗑️

No Wastage Tracking

Unused stems post-event are discarded with no record. No data to improve recipe accuracy or set smarter vendor quantity recommendations.

💸

No Margin Visibility

Cost per event calculated after delivery, not before. Impossible to price correctly or flag unprofitable events early enough to intervene.

Cost of Inaction: For a studio running 80–120 events/year at $3,500–$8,000 average floral budgets, inefficiencies conservatively represent $40,000–$120,000 in recoverable lost margin annually.

Section 15 — AI Feature Roadmap

Seven AI-powered features

FloraFlow is architected from day one to support AI augmentation via the Anthropic Claude API. Intelligence layers are phased to build on validated operational data.

Phase 2 — AI-1

Smart Recipe Suggestions

Analyses an event profile and recommends recipe combinations from the library that match the aesthetic and stay within budget.

Input

Event type, style tags, colour palette, guest count, budget

Output

Ranked list of recipe combinations with estimated total cost

Phase 2 — AI-2

Seasonal Substitution Alerts

Before PO generation, checks the event's flower list against seasonality data and suggests in-season alternatives with cost and aesthetic impact notes.

  • Reduces reliance on premium out-of-season pricing
  • Suggestions require designer approval — no auto-changes
  • Includes cost delta and visual similarity score
Phase 2 — AI-3

Buffer Intelligence

Replaces static 10% buffer with dynamic recommendations derived from historical wastage data per variety and event type.

  • Example: "Peonies average 22% wastage in summer — recommend 25% buffer"
  • Continuously improves as post-event wastage data accumulates
  • Per-variety, per-season, per-event-type granularity
Phase 3 — AI-4

Natural Language Event Build

A designer describes an event in plain English and receives a complete draft build with recipe suggestions, stem counts, and cost estimate.

Prompt

"Garden romantic wedding, 200 guests, chuppah, 24 centerpieces, blush and ivory, $12k budget."

Output

Draft event build with matched recipes, quantities, 2,400 stems, $5,800 est. cost

Phase 3 — AI-5

Pricing Intelligence

Analyses historical margins, market pricing trends, and complexity to suggest optimal pricing for new events. Flags proposals that are historically underpriced.

  • Surfaces underpriced proposals before they're sent
  • Compares to similar past events with known margins
  • Flags arrangement complexity vs. quoted rate
Phase 3 — AI-6

Client Proposal Narrative

Given an event build and client brief, generates the descriptive narrative for proposals in brand-appropriate language — describing the floral vision and seasonal selections.

  • Studio voice training from prior accepted proposals
  • Includes seasonal flower callouts and design intent
  • Designer reviews and edits before sending
Phase 3 — AI-7

Vendor Negotiation Intelligence

Analyses PO history, current pricing, and purchase volume to identify the best timing and leverage points for renegotiating vendor pricing. Surfaces recommendations to Operations Manager with supporting data.

  • Identifies price creep per variety across vendor invoices
  • Flags when volume thresholds are approaching discount tiers
  • Suggests optimal consolidation windows for multi-event orders

Critical Concerns & Feature Gaps

Issues that should be addressed before launch to avoid operational failures or adoption friction.

01
Critical

Vendor-Flower Preference Matrix

PO generation requires knowing which vendor supplies which flower. Without a preference matrix, all stems default to one vendor — defeating multi-vendor ordering logic.

  • UI: per-flower vendor ranking table in Catalog
  • Fallback: first active vendor if no prefs configured
  • Phase 2: ML ranking from fill rate history
02
Critical

Recipe Cost Alert Threshold

Silent margin erosion from supplier price increases is a known risk. Each recipe should have an optional max cost-per-unit threshold with email + in-app alerts.

  • Per-recipe threshold (e.g., "alert if centerpiece > $45/table")
  • Triggered on catalog price update or recipe save
  • Notifies head designer and owner
03
Feature Gap

Event Day Production Checklist

Missing from the original PRD: designers and warehouse staff need a structured day-of checklist per room and arrangement — currently managed on paper or verbally.

  • Auto-generated from event build per location
  • Checkbox items: arrangement name, stem count, notes
  • Mobile-optimized; status syncs to event record
04
Feature Gap

Event Cloning / Templates

Any completed event can be saved as a named template (e.g., "Standard 100-Guest Wedding"), pre-filling the entire arrangement build for the next event.

  • Eliminates re-entry for recurring corporate florals
  • Managed by Head Designer and Owner
  • API: POST /events/:id/duplicate
05
Feature Gap

Proposal Expiry & Auto-Reminders

Proposals need a configurable expiry date (default: 14 days). Automate the reminder loop so account managers don't need manual follow-up tracking.

  • Client reminder email 3 days before expiry
  • Status auto-moves to expired on due date
  • In-app prompt for account manager to follow up
06
Feature Gap

Recipe Similarity Detection

As the recipe library grows, duplicate and near-duplicate arrangements create catalog noise. An automated similarity check prevents recipe sprawl.

  • Cosine similarity on stem ingredient vectors
  • Flagged on publish if >85% match to existing recipe
  • Offer merge or archive workflow
07
Feature Gap

Vendor Substitution Workflow

When a vendor cannot fill a line item, there is no structured substitution path. The operations manager should have a one-click secondary vendor allocation.

  • Triggered on partial PO receipt or fill-rate alert
  • Pulls priority-2 vendor from preference matrix
  • Creates a supplemental PO for the shortfall quantity
08
Feature Gap

Consolidated Multi-Event PO

Luxel often has multiple events in the same week from the same vendor. A consolidated PO reduces ordering overhead and may unlock volume discounts.

  • Select multiple events → aggregate stems by flower → generate single PO
  • Event breakdown shown as sub-table within PO
  • Phase 2 feature; requires inventory netting per event

Architectural Alternatives

Design decisions that have meaningful trade-offs — evaluate before Phase 2 build begins.

09
Architecture

PWA Over Native Mobile (Phase 3)

The original PRD proposed native iOS/Android apps. A Progressive Web App (PWA) with Service Workers delivers equivalent warehouse UX at significantly lower build cost.

  • Offline receiving + wastage entry via Service Worker cache
  • Add-to-home-screen works on iOS 16.4+ and all Android
  • One codebase instead of three — React web app already built
  • Evaluation trigger: if barcode scanning requires native camera APIs → go native
10
Architecture

Supabase Auth Migration Path

Phase 1a uses JWT with local SQLite. Phase 1b should migrate to Supabase Auth with Row-Level Security to enable proper multi-user collaboration without building custom auth.

  • Email + magic link out of the box
  • RLS policies enforce company_id isolation at DB layer
  • Migration path: swap JWT middleware → Supabase JWT verify
  • No data migration needed — schema is already multi-tenant
11
Architecture

Dynamic AI Buffer Tuning

The static category buffer matrix is a good baseline, but Phase 2 should learn from post-event wastage data to tune buffers per flower per event type automatically.

  • Input: wastage entries with flower, category, event type, season
  • Model: simple regression or EWMA per (flower, category) pair
  • Output: recommended buffer % shown in recipe editor with confidence score
  • Head designer can accept or override
